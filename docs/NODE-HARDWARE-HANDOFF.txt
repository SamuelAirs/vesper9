USB INPUT, LIGHT AND AUDIO NODE

HARDWARE

- ESP32-S3 N16R8: 16 MiB flash, 8 MiB PSRAM.
- One momentary arcade button, with separate press and release events.
- Four RGB lamps arranged left to right. Each of the twelve color channels
  supports independent brightness from 0 to 255.
- Two INMP441 digital microphones, positioned left and right.
- One additional WS2812 RGB LED on the development board, controlled separately
  from the four lamps. Power and TX/RX indicators are not software-controlled.
- No temperature/humidity sensor, accelerometer or dedicated tap sensor.
  Case taps are detected using the microphones.
- No audio-output interface in the installed firmware; sound playback belongs
  to the connected computer.

CONNECTION

Use the accessible native USB connector. The separate UART/COM connector is
inside the case and should not be needed. Normal operation requires no case
opening, rewiring or firmware replacement.

The device presents an ESP32-S3 USB Serial/JTAG serial interface. It normally
appears as /dev/ttyACM* on Linux or COM* on Windows. A Windows COM number refers
to this same USB connection, not the inaccessible physical COM connector.
USB serial identity: DC:DA:0C:14:8F:C0.

The interface carries a binary protocol, not text commands or standard USB
gamepad, MIDI or audio data. A host application reads inputs and sends light/
audio-control commands. Native USB ignores the UART baud rate; 921600, 8N1,
no flow control matches the existing configuration. Keep DTR and RTS false
before opening. Only one application should own the serial connection.

INSTALLED FIRMWARE

Version 0.2.0, board profile 2; last device confirmation 2026-10-03.
Implementation: ESP-IDF C, with a 5.4.2 build toolchain.

The firmware handles button debounce, lamp PWM, board LED output, synchronized
microphone acquisition, acoustic tap detection and timed light sequences.
Gesture meanings, application controls, speech recognition and optional tap-side
classification are host software responsibilities.

Send PING about once per second. After three seconds without a valid host frame,
the device stops audio streaming and tap detection, cancels scheduled lights,
and turns the lamps and board LED off. Reapply desired settings after reconnect.

GPIO MAP

These are the actual RGB assignments used by the firmware. Send RGB values
in ordinary red/green/blue order; no additional host-side color swap is needed.

Component                       GPIO
Lamp 1, left: R / G / B           7 / 16 / 15
Lamp 2:       R / G / B          17 /  8 / 18
Lamp 3:       R / G / B           9 / 11 / 10
Lamp 4, right: R / G / B         13 /  3 / 14
Left mic:  BCLK / WS / data       4 /  5 /  6
Right mic: BCLK / WS / data      47 / 45 / 21
Button input                    12, active-low with internal pull-up
Button return                   46, driven low by firmware
Board WS2812 data                48
Native USB D- / D+               19 / 20

The switch closes between GPIO12 and GPIO46. Microphones use 3.3 V; grounds
are common. Main lamps have active-high discrete color legs with existing
current limiting. PWM is 4 kHz with approximately gamma-2.2 brightness mapping:
eight channels use LEDC and four use MCPWM. The board LED uses RMT, with RGB
commands converted internally to the WS2812's GRB wire order.

BUTTON, TAPS AND MICROPHONES

Button events are emitted after 8 ms stable debounce and timestamped at the
initial edge. A button held at startup is inhibited until released.

Both microphones are clocked from the same source. Audio is signed 16-bit
little-endian PCM at 16 kHz. Mono packets normally contain 320 samples (20 ms);
stereo packets contain 160 left/right pairs (10 ms), usually delivered as two
packets after a 20 ms read. Use sample indices, not USB arrival times. Firmware
discards 300 ms on acquisition startup and applies a roughly 25 Hz DC filter.

The left microphone detects taps; short stereo clips allow the host to attempt
side classification. A tap verdict takes roughly 90 ms plus transport latency,
and detected onsets must be at least 150 ms apart. Threshold 4000 is a useful
starting point; higher values are less sensitive. Firmware accepts 256..32767,
or zero to disable detection. It suppresses taps within 60 ms of button edges.

Comfortable back-of-case taps work as generic input. Left/right classification
can be useful after calibration, but back taps cannot reliably be distinguished
from side taps. The firmware sends no left/right label; classification must be
implemented on the host. Claps and speaker vibration can also trigger taps.

MIC=0 stops continuous audio streaming, but microphones still acquire samples
when tap detection is enabled. Accepted taps can send an 11 ms stereo clip even
with streaming off. Send both MIC=0 and KNOCK_SET=0 to stop those functions;
this does not physically cut power to the microphone modules.

USB PROTOCOL

All numeric fields are little-endian. Each frame is:
  'V9' | u8 version=1 | u8 type | u16 sequence | u16 payload_length
       | payload | u16 CRC

Payload limit: 768 bytes; frame size: payload + 10 bytes. Sequence wraps at
65536. CRC-16/CCITT-FALSE covers version through payload, excluding magic:
polynomial 0x1021, initial 0xFFFF, no reflection/final XOR. Test vector:
ASCII '123456789' -> 0x29B1. Buffer partial reads and resynchronize after errors.

Host commands (decimal type numbers):
16 PING       Empty; returns STATUS.
17 LEDS       12 bytes: R1,G1,B1,R2,G2,B2,R3,G3,B3,R4,G4,B4.
18 MIC        One byte: 0 stop streaming, 1 left mono, 2 stereo.
19 ARM        u32 trial_id, u32 delay_ms, u8 logical_light, u8 R,G,B.
              Delay 250..10000 ms; logical light 0=left, 1=both middle,
              2=right. Emits CUE when the light activates.
20 CANCEL     Empty; cancels scheduled cue/pattern without changing lamp values.
21 PATTERN    u8 repeats(1..8), u8 step_count(1..16), then steps of
              u16 duration_ms(10..10000) followed by 12 RGB bytes.
22 KNOCK_SET  u16 threshold; zero disables tap detection.
23 BOARD_LED  Three bytes: R,G,B for the board LED.

LEDS and PATTERN also accept legacy nine-byte RGB groups, duplicating the
middle triplet across the two middle lamps. Use twelve for independent control.

Device messages:
1 HELLO       UTF-8 JSON status at startup.
2 BUTTON      u64 initial_edge_at_us, u8 pressed.
4 AUDIO       u32 first_sample_index, then mono s16 samples.
5 CUE         u32 trial_id, u64 activated_at_us.
6 STATUS      UTF-8 JSON, approximately once/second and after PING.
7 ACK         u16 command_sequence, u8 result, u8 command_type.
              Result: 0 accepted, 1 invalid payload, 2 unknown command.
8 KNOCK       u64 at_us, u16 peak, u8 hf (acoustic brightness).
9 AUDIO2      u32 first_frame_index, then interleaved L,R s16 pairs.
10 KNOCK_CLIP u64 at_us, u8 pre_frames=16, u8 channels=2, then 176 stereo
              s16 frames. Payload is 714 bytes. Precedes its matching KNOCK.

BUTTON, KNOCK and CUE use the same device microsecond clock, which resets at
reboot. Match clips to knocks by timestamp. Audio indices wrap at 2^32.
Useful STATUS fields: fw, board=2, lamps=4, mics=2, link='usb', mic, stereo,
mic2, slots, button, leds, board_led, knock, audio_drops and rx_crc.

IMPLEMENTATION TIPS AND KNOWN ISSUES

- Low speaker tones can shake the case into false taps. Suppressing tap input
  during self-generated tones below 140 Hz, plus a 250 ms tail, helped in use.
  This needs host-side handling; the firmware alone does not prevent it.
- The button's mechanical click can register acoustically. Extra host filtering
  may help, but suppressing taps throughout a button hold also prevents intended
  hold-plus-tap controls. Choose that tradeoff deliberately.
- Brightness-based rejection of sharp sounds is currently disabled; do not
  treat the hf field as proof that a sound was an intentional case tap.
- Check mic2 setup/read errors and actual samples. A reported two-microphone
  capability does not prove both channels are currently producing good audio.
  MIC acknowledgement alone is not confirmation of capture; inspect STATUS.
- LEDS cancels PATTERN but leaves ARM scheduled. For complete cleanup send
  CANCEL, explicit main-lamps off and explicit board-LED off.
- Cancel unfinished button holds/actions on disconnect or reboot. Do not mix
  device timestamps across boots or subtract them from a host wall clock.
- USB flashing has worked without opening this case. If replacing firmware,
  preserve a verified full 16 MiB backup first and explicitly select board 2.
  Preserve USB Serial/JTAG and GPIO19/20; disabling USB or changing sleep
  behavior can leave recovery dependent on inaccessible boot/reset controls.
- GPIO3, GPIO45 and GPIO46 are strapping pins. Preserve their existing wiring
  and startup configuration when changing firmware.
