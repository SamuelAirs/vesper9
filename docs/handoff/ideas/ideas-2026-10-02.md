# Vesper 9: new game, UI and performance ideas (2026-10-02)

Nothing here is built yet. Pick any and I'll start it (or hand it to the thread that owns that area).

## New games

All four are button and lamps only. None uses temperature, humidity or case taps, and none needs the mic.

### 1. Signal Box (lamps first, flow)
You're the signalman at a junction where three lines meet, and each lamp is one line's signal. Trains roll in from the dark, and the lamp for their line warms from green to amber to red as they get close. Tap to step the "clear" signal to the next line. Hold to clear the line that's been waiting longest. Let a train wait too long and it brakes, which costs points. Switch at the wrong moment and two trains share a crossing. You can play it mostly from the lamps, with the screen there for the map.
- **Pace:** a shift runs about 3 minutes and gets busier through the night. Expresses can't wait and freight can.
- **Depth:** new junctions to unlock (a branch line, a loop, a level crossing), a timetable that rewards rhythm, and a daily shift.
- **Why it fits:** it's lamp-focused one-button play like Meridian, but it's about managing a flow, not timing a single press.

### 2. Three Suns (press your luck, a roguelite run)
Tap to draw. Each draw lights a lamp red, green or blue. Three of a colour, or one of each, scores a combination. A clash (two of one colour and one of another, in the wrong order) busts the hand. Hold to bank. Between rounds you pick one of three relics ("blue draws twice", "a bust keeps half"). A run lasts eight rounds against a rising target.
- **Pace:** it's never twitchy, so there's no unfair difficulty. Each decision takes a second.
- **Depth:** relic builds, a daily seed, and an unlock ladder like Balatro's. Bots can tune the odds.
- **Why it fits:** "draw or stop" is a natural one-button choice, and nothing like it is on the console.

### 3. Curfew (hold to move, a stealth run)
Hold to creep across a rooftop town, and let go to freeze in place. The lamps show the searchlight: dark means safe, a slow amber pulse means it's turning your way, and red means don't move. Each district adds something new: guards whose light flickers before they turn, dogs that hear you if you hold too long, and a moon that brightens the lamps.
- **Pace:** levels last 20 to 40 seconds and retry instantly. The rhythm comes from reading the lamps.
- **Depth:** about 30 hand-built districts plus a daily one. You can collect a stash in each district, which is optional and a riskier route.
- **Why it fits:** it's "red light, green light" played on the lamps. You learn it in five seconds, and the tension builds on its own.

### 4. Pass the Node (party games)
These are short games for two to six people sharing the one button: Bomb Squad (tap back the code the lamps flash, then pass the node), Hot Lamp (hold it until the lamp tells you to pass), and Steady Hands (whose hold lands closest to 3 seconds). The screen keeps score.
- **Why it fits:** one shared button makes hot-seat games work naturally, and the console has nothing for a room full of people.

## UI ideas
Dashboard layout belongs to the "Tidy the dashboard layout and visuals" thread, so these would go there.

1. **Continue tile.** The dashboard opens with your last game selected, so one hold gets you back in. With about 25 apps and tap-to-step navigation, reaching a game can take 10 or more taps today.
2. **Order by play.** Your most-played games go first, and instruments and system tools move to a second row.
3. **Today's three.** Each day there's a challenge in three different games (for example "Perihelion: cross two regions", "Ricochet: clear 3 boards"). The lamps on the dashboard show how many you've done. It's a reason to come back that spans the whole console.
4. **Attract mode.** When the console sits idle, it plays itself: it cycles demo runs of the games, driven by the simulated players the game threads already wrote for balancing. The lamps follow the play. Any press goes back to the dashboard.

## Performance (measured)

**How I measured:** headless desktop Chromium with software rendering, CPU slowed 6×, at Sam's 1024×600 screen size. It starts each game, taps through some play, and counts frames that took longer than 20 ms. **This is not a Pi measurement.** The Pi is the real test. The script is [frame-check.cjs](/mnt/project-files/ideas/frame-check.cjs).

| Build | Slow frames |
|---|---|
| main: every game | 0 to 3% |
| Perihelion visual pass (PR #1) | ~52% (it runs at 30 fps much of the time) |
| Moonrunner zones (PR #3) | ~47% |
| Ballista visual pass (PR #6) | ~20% |
| Outpost visual pass (PR #8) | ~8% |
| Meridian (PR #9) | under 1% |

Main runs comfortably. The new visual passes are what will stutter on the Pi.

1. **Draw the game at the size it's shown.** The game canvas is 960×540, but on the 7" screen it's displayed at 670×377 (0.7 scale), so every frame paints about twice the pixels anyone sees. Changing the canvas to 672×378 and scaling the drawing by 0.7 (two lines in `web/main.js` and `web/index.html`, with no game changes) cut Perihelion PR #1's slow frames from ~52% to ~14–17% in the same test. It should also make text sharper, because nothing gets downscaled.
2. **Cache glows and backgrounds.** Perihelion's pass builds a full-screen radial gradient plus a gradient for every glow on every frame. Tideline and Outpost build five gradients a frame, and Moonrunner repaints its ground strips. A shared `glow()` sprite cache and a pre-rendered backdrop per zone in `web/engine/draw.js` would let each game copy an image instead of re-rasterizing.
3. **Freeze the game behind the menu.** When the menu is open, the game is paused, but `frame()` in `web/main.js` still redraws it 60 times a second under the overlay's `backdrop-filter: blur(4px)`, so the blur is recomputed on every frame. Skipping the draw while paused makes the menu cost almost nothing.
4. **Add a frame budget check to the suites.** Run the script above on each game branch and fail if more than 10% of frames are slow. A visual pass would then show its cost before it reaches the Pi.
5. **Check the Pi's GPU (one look, then decide).** `scripts/kiosk.py` starts Chromium with no GPU flags. Opening `chrome://gpu` once on the Pi shows whether canvas drawing is GPU-accelerated there. If it isn't, enabling it may be the biggest single win, but only the Pi can tell us.
